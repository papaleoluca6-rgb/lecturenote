# Piano: righe 7, 9, 10, 11 della roadmap

Spec: `CLAUDE.md` (regole del progetto) + `docs/ROADMAP.md` (righe 7, 9, 10, 11). Nessun altro documento di specifica.

## Global Constraints

- App PWA per tablet Android (Samsung Galaxy Tab Active2, Android 9, Chrome non recentissimo, CPU modesta). Vite + React 19 + TypeScript + Dexie.
- **Tutto gratuito; l'app funziona senza chiavi API.** Le AI esterne sono solo facoltative, mai default.
- Ogni funzionalità vive in `src/features/<nome>/`. Una feature importa da altre feature **solo** tramite `src/db/` o `src/lib/`. La composizione tra feature si fa in `src/app/`.
- File piccoli: < 200 righe. Componenti `*.tsx`, logica `*.ts`.
- `src/db/schema.ts` è l'unico modello dati. Non modificare `db.version(1)`; campi nuovi non indicizzati non richiedono una nuova versione.
- Una sola timeline: ogni elemento ha `ts` = secondi dall'inizio della lezione.
- Audio e immagini come `Blob` in IndexedDB, mai base64.
- Chiavi API solo nelle impostazioni dell'app (`db.settings`, chiave `apiKey.<provider>`, es. `apiKey.gemini`), mai nel codice.
- UI in italiano, touch: tap target ≥ 44px, layout per tablet orizzontale e verticale.
- Colori e misure solo tramite variabili CSS di `src/styles/global.css` (si possono aggiungere token lì).
- Non leggere `legacy/` per intero (~58k token): solo grep mirati.
- Verifica minima per ogni task: `npm run build` e `npm run lint` senza errori (l'avviso già esistente su `scripts/copy-pdfjs.mjs` è noto). Non esiste una suite di test: non aggiungerne una.
- Utility esistenti da riusare: `fmtSecs` in `src/lib/time.ts`; per gli object URL di Blob vedere il pattern in `src/features/slides/useBlobUrl.ts` (non importarlo: copiare il pattern nella propria feature se serve).

## Contesto per tutti i task

- `src/app/App.tsx`: navigazione. Libreria (`LibraryScreen`) → `RecordingScreen` (prop `panels(clock)` dove `clock = { recording: boolean; now: () => Sec }`). Hash `#prova` apre la pagina di prova del traduttore.
- `src/app/LessonPanels.tsx`: schede «Slide / Pagine bianche» sotto il registratore, con `InkToolbar`; entrambi i pannelli restano montati (attributo `hidden`).
- `db.notes`: `Note { id, lessonId, ts, text, photo?: Blob, createdAt }`, indici `id, lessonId, ts`.
- `db.settings`: `Setting { key, value }`.

### Task 1: Note di testo e foto con timestamp (riga 7, `src/features/notes/`)

Costruire `NotesPanel({ lessonId, now }: { lessonId: Id; now: () => Sec })`:
- Campo di testo multiriga + bottone «Aggiungi nota» → `db.notes.add` con `ts = now()` arrotondato a 0,01 s, `createdAt = Date.now()`. Il `ts` è preso quando si **inizia** a scrivere la nota (primo carattere digitato), non quando si preme «Aggiungi», così la nota resta legata al momento giusto; se il campo viene svuotato il momento si azzera.
- Bottone «📷 Foto»: `<input type="file" accept="image/*" capture="environment">`. L'immagine viene ridotta a lato lungo massimo 1600 px, JPEG qualità 0.85, salvata come `Blob` in `photo` (con il testo del campo, se c'è, come didascalia). `ts` = momento dello scatto/scelta.
- Elenco delle note della lezione ordinate per `ts`: tempo (`fmtSecs`), testo, miniatura della foto (object URL revocato correttamente; `loading="lazy"`). Tocco sulla miniatura → foto a tutto schermo con chiusura.
- Modifica del testo di una nota esistente (salvataggio al blur) ed eliminazione con conferma.
- Integrazione: in `src/app/LessonPanels.tsx` aggiungere la terza scheda «Note»; `InkToolbar` va mostrata solo nelle schede «Slide» e «Pagine bianche». Anche il pannello note resta montato (attributo `hidden`).
- Le note si possono scrivere sia durante la registrazione sia dopo (con `now()` = fine lezione).

### Task 2: Impostazioni (riga 9, `src/features/settings/` + `src/db/settings.ts`)

- `src/db/settings.ts`: helper tipizzati per leggere/scrivere `db.settings` usabili da tutte le feature: `getSetting<K>(key)`, `setSetting<K>(key, value)` e un hook `useSetting<K>(key)` (con `useLiveQuery`). Chiavi e default:
  - `apiKey.gemini`: string, default `''` (stessa chiave usata dalla prova traduttore in `src/features/translation/probe/config.ts`).
  - `stt.provider`: `'webspeech-device' | 'webspeech' | 'gemini-chunks'`, default `'webspeech-device'`.
  - `translator.provider`: `'chrome' | 'gemini'`, default `'chrome'`.
  - `ui.recordingDefaultLang`: `SpokenLang`, default `'zh+en'`.
- `SettingsScreen({ onClose, children })` in `src/features/settings/`: titolo «Impostazioni», bottone «← Libreria»; sezioni:
  1. «Riconoscimento del parlato» (scelta `stt.provider`, con spiegazione breve: sul dispositivo = gratis e offline se Chrome lo supporta; Web Speech = server Google, serve VPN in Cina; Gemini = facoltativo, serve chiave).
  2. «Traduzione» (scelta `translator.provider`: Chrome offline / Gemini).
  3. «Chiave AI facoltativa»: campo password per la chiave Gemini con mostra/nascondi, salva, cancella; testo che spiega che è facoltativa, gratuita nel piano free, e resta solo sul tablet. Le opzioni Gemini nelle sezioni 1 e 2 sono disabilitate finché non c'è una chiave, con la nota «richiede una chiave».
  4. `children` in fondo (spazio per il backup del Task 3).
- Navigazione: in `App.tsx` hash `#impostazioni` → `SettingsScreen` (chiusura: `location.hash = ''`). In `LibraryScreen` aggiungere nell'header un bottone/link «⚙ Impostazioni» accanto a «Prova traduttore» (stesso stile).
- Nessun test di rete della chiave in questo task.

### Task 3: Backup completo (riga 10, `src/features/backup/`)

- Formato file `.lnbak` (binario, niente base64, adatto a ore di audio):
  - riga 1: `LECTURENOTE-BACKUP 1\n`
  - riga 2: lunghezza in byte (decimale) del JSON UTF-8 che segue, poi `\n`
  - JSON: `{ "version": 1, "createdAt": <ms>, "dbVersion": <db.verno>, "tables": { "<nome>": [record...] } }`, dove ogni `Blob` nei record è sostituito da `{ "__blob": { "offset": n, "size": n, "type": "..." } }` (offset relativo all'inizio della sezione binaria).
  - sezione binaria: i Blob concatenati.
  - Il file si costruisce con `new Blob([...parti])`, senza mai creare una stringa con i dati binari.
- Tabelle esportate: tutte quelle di `db` (`db.tables`). Da `settings` si **escludono** le chiavi che iniziano con `apiKey.` (le chiavi API non escono dal tablet).
- `exportBackup(): Promise<Blob>` e download come `lecturenote-backup-AAAA-MM-GG.lnbak` (link con `download` e object URL revocato dopo).
- `importBackup(file: File, onProgress)`: valida intestazione e versione, legge il JSON con `file.slice`, ricostruisce ogni Blob con `file.slice(offset, offset+size, type)` (i blob restano riferimenti al file finché non scritti), poi `bulkPut` tabella per tabella in un'unica transazione `rw` su tutte le tabelle. Modalità unica: **unisce** (gli elementi con lo stesso id vengono sovrascritti, gli altri restano). Errori leggibili in italiano per file non valido / versione non supportata.
- `BackupPanel` (UI): sezione «Backup» con «Esporta tutto» (mostra dimensione del file creato) e «Importa backup…» (input file `.lnbak`, conferma prima di importare, avanzamento, esito con numero di elementi per tabella).
- Integrazione: `BackupPanel` va passato come `children` di `SettingsScreen` in `src/app/App.tsx` (la composizione tra feature si fa in `app/`).
- L'import dei vecchi JSON di `legacy/` **non** fa parte di questo task (resta da fare; annotarlo).

### Task 4: PWA installabile (riga 11)

- Script `scripts/make-icons.mjs` (Node, solo moduli built-in: `zlib`, `fs`) che genera PNG senza dipendenze: `public/icons/icon-192.png`, `public/icons/icon-512.png`, `public/icons/maskable-512.png`. Disegno: sfondo `#5b5fff` (accent), simbolo semplice e leggibile in bianco (es. una nota/pagina stilizzata con un punto rosso `#ff4055` di registrazione). Per la versione maskable il simbolo sta nella safe zone (80% centrale) e lo sfondo copre tutto. Lo script va eseguito una volta e i PNG vanno committati; aggiungere `"icons": "node scripts/make-icons.mjs"` agli script di `package.json`.
- `vite.config.ts`: manifest con icone 192 e 512 (`purpose: 'any'`) e la maskable (`purpose: 'maskable'`), mantenendo `favicon.svg`; togliere il TODO; aggiungere `start_url: '/'`, `scope: '/'`, `id: '/'`. `includeAssets` deve includere le icone; `globPatterns` deve includere `png`.
- `index.html`: `<link rel="apple-touch-icon" href="/icons/icon-192.png">` e `<meta name="theme-color" content="#0b0b12">` se mancano.
- Verifica: `npm run build` e controllare che `dist/manifest.webmanifest` contenga le icone e che `dist/sw.js` precachi i PNG.
